## 三、这些项目普遍没做好的五件事（空白点）

1. **回测-实盘一致性**：只有 NautilusTrader、Lean、Jesse、vn.py 做到同一份代码两端运行；Qlib、vectorbt、RQAlpha、FinRL 都止于研究，排队、部分成交、延迟的假设与真实差距大。
2. **成本与容量建模缺失**：多数引擎只有"固定手续费 + 固定滑点 bps"，不建模冲击成本、借券费、涨跌停/停牌、T+1。**cvxportfolio 是少数把交易成本写进优化目标的。**
3. **LLM/多智能体框架缺可复现评估**：输出叙事型决策，没有 walk-forward、成本与统计显著性。
4. **风控只到组合层**：pre-trade 限额、kill switch、单标暴露上限在多数 RL/LLM 项目里完全缺失。**freqtrade 的 protector、NautilusTrader 的 risk engine 是少数可直接抄的。**
5. **中国市场数据与执行断层**：免费源普遍没有 PIT、退市股、Level-2；A 股没有正规开源下单通道。

## 四、读码顺序建议

```
vectorbt（半天理解向量化）
  → Lean 或 NautilusTrader（事件驱动 / 撮合 / 券商抽象）
  → vn.py 的 Gateway（国内柜台）
  → Qlib（因子流水线）
```

**不要从 LLM 交易框架入门**——代码短，工程参考价值低。

## 五、无本金也能做的真实 API 验证

**Alpaca paper key 免费**，`alpaca-py` + Lean/Nautilus 可以跑通"下单→成交→持仓"全链路。
这是从回测跨到执行成本最低的路径，且不需要真钱。

> 这条对我们的价值：如果能用 paper 账户验证一次完整链路，"执行层完全空白"这个断点就能部分填上——**虽然不是实盘，但至少证明代码通**。
