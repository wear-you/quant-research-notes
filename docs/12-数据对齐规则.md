# 12 · 数据对齐规则（一次严重错误的产物）

> 这条规则的由来：2026-11-16 发现，此前公布的"夏普 1.88"是**日期错位**造成的假象，
> 按日期严格对齐后真实值是 **0.47**。

## 一、错在哪

多资产回测里，代码长这样：

```python
L = min(len(s) for s in series)
portfolio = [sum(s[i][1] for s in series) / len(series) for i in range(L)]
```

看起来"取了最短长度"很安全，但**索引 i 在不同资产上对应不同的日历日期**：

| 资产 | 起始 | 索引 1000 对应 |
|---|---|---|
| 上证综指 | 1990-12-19 | 约 1995 年 |
| 沪深300 | 2002-01-04 | 约 2006 年 |
| 中证500 | 2005-01-04 | 约 2009 年 |

把 1995 年的波动和 2009 年的波动平均在一起，等于凭空造出一个"跨时代分散化"的组合——
波动被人为压低，夏普被系统性抬高。

## 二、后果有多大

| 指标 | 错位版 | 日期对齐 |
|---|---|---|
| VOLT 夏普 | 1.88 | **0.47** |
| 买入持有夏普 | 0.71 | **0.17** |
| VOLT 年化 | 5.08% | **2.61%** |
| 买入持有年化 | 5.62% | **1.49%** |

**相对优势（2.7~2.8 倍）几乎没变，绝对水平全部腰斩。**
这也说明：错误如果同时作用于两组序列，比值会骗过你。

## 三、现在的规则

`market.py` 是唯一的数据对齐层：

```python
from market import panel, portfolio, perf, print_coverage

print_coverage(names)          # 先打覆盖表
dates, px = panel(names)       # 只保留共同交易日
per_asset = {...}              # {资产: {日期: 收益}}
port = portfolio(per_asset)    # 按日期交集平均，不按索引
p = perf(port)
```

三条硬约束：

1. **禁止按索引对齐不同起始日的序列**——`portfolio()` 只接受 `{date: value}` 字典
2. **任何组合计算前先打印覆盖表**
3. **缺失日期不插值**，直接剔除

## 四、覆盖表能直接暴露问题

对当前 34 个序列执行 `python3 market.py`：

```
共同区间 2020-10-13 → 2026-11-16，共同交易日 1433 天
```

34 个资产只有 1,433 天共同历史（因为 AVAX/DOT 2020 年才上市）。
**任何人拿这 34 个资产做"全历史组合回测"，只要没按日期对齐，结果必然是假的。**

## 五、守卫

- `holdout.py` 已废弃：直接运行会拒绝并提示改用 `verify_holdout.py`
- 每日任务新增"日期对齐检查"，打印共同交易日
- `market.assert_same_dates(a, b)` 可在合并前主动断言

## 六、这条规则的一般形式

> **凡是"按位置配对"的操作，都要先问：这两个位置是同一个时间吗？**
>
> 同样的错误也会出现在：多个 CSV 按行号对齐、多策略结果按顺序合并、
> 日志按行号对照时间戳、以及任何"取了最短长度就安全"的假设。
