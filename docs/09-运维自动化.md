# 09 · 运维：自动化与自检

> 这套系统的设计目标是：**不需要人盯着，也不允许自己偷偷改参数。**

## 一、自动化时间表

| 任务 | 时间 | 做什么 |
|---|---|---|
| `finance-daily` | 每天 16:40（Asia/Shanghai） | 拉行情 → 数据闸门 → 纸面账本 → 自检 → 10 行简报 |
| `finance-monthly-review` | 每月 1 日 09:00 | 结算反思 → PBO 闸门 → 自检 → 15 行月报 |

网关由 launchd 托管（`~/Library/LaunchAgents/ai.hermes.gateway.plist`，`RunAtLoad=true`），**开机会自动拉起**，所以这两个任务不需要手动启动。

## 二、自检（`health.py`）

四项检查，任何一项 FAIL 都会让 cron 退出码非零：

| 检查 | 判据 |
|---|---|
| **A 数据** | 每个序列末条距今 ≤10 天；根数 ≥300 |
| **B 账本** | 无重复键、净值 >0、仓位 ∈ [0,1]、相邻记录间隔 ≤10 天 |
| **C 参数锁** | `paper.py` 里的 WINDOW / TARGET_VOL / CASH_RATE 与 `params.lock.json` 一致 |
| **D 运行** | 最近一次日报在 48 小时内 |

输出：`~/finance/health/latest.md` 与 `latest.json`。

### 为什么要有参数锁

因为最容易犯的错，不是策略错，是**自己偷偷改参数然后把结果当成新证据**。
一旦 `paper.py` 里的冻结值被改动，自检直接 FAIL，cron 简报第一句就是「❌ 自检失败」。

**参数是锁住的，不是靠自觉。**

## 三、失败时的行为

| 环节 | 失败表现 | 后果 |
|---|---|---|
| 行情拉取 | 主源 WAF / 返回 HTML | 自动降级（akshare → 腾讯 → 新浪），并按日期**合并**写入，不会缩短历史 |
| 数据过期 | 末条 >10 天 | 移入 `data/_quarantine/`，不参与回测 |
| 自检 | 任一 FAIL | cron 退出码非零，简报首句必须写「❌ 自检失败」并原样列出 |
| 参数漂移 | 冻结值被改 | 直接 FAIL |

## 四、手动入口

```bash
cd ~/finance
.venv/bin/python fetch.py          # 只拉数据
python3 check_data.py              # 数据闸门
python3 paper.py --report          # 更新账本 + 生成日报
python3 health.py                  # 自检
python3 reflect.py                 # 结算 + 反思（全历史）
python3 validate.py --long         # PBO / DSR
python3 holdout.py                 # 真样本外（一次性的，别反复跑）
```

## 五、不该做的事

- ❌ 不要为了让指标好看去改 `WINDOW` / `TARGET_VOL` / `CASH_RATE`——参数锁会 FAIL
- ❌ 不要在 `holdout.py` 上反复试参数——那会把样本外变成样本内
- ❌ 不要把纸面净值当真实收益
- ❌ 不要在数据过期时继续跑回测（闸门会自动拦，但人也要知道）
